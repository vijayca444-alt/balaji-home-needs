BALAJI HOME NEEDS — CUSTOMER LOGIN + STORE PASSWORD RESET

WHAT THIS UPDATE PROVIDES
- Customer registration: full name, unique username, mobile number, email and password.
- Email verification is NOT required. Customer can sign in immediately after registration.
- Customer login accepts username OR email + password.
- Forgot password message tells customers to contact the store.
- Admin dashboard has a Customers & Passwords tab.
- After verifying a customer's identity by phone, the admin can generate a temporary password.
- The customer is prompted to change that temporary password after the next login.
- Guest checkout remains available.
- Existing store Admin login remains separate and unchanged.

STEP 1 — DATABASE MIGRATION (RUN ONCE)
1. Open the Supabase project dashboard.
2. Open SQL Editor > New query.
3. Open CUSTOMER-LOGIN-SUPABASE-MIGRATION.sql from this project.
4. Copy all SQL into the editor and click Run.
5. Confirm it completes without errors.

STEP 2 — TURN OFF CUSTOMER EMAIL CONFIRMATION
1. Supabase Dashboard > Authentication > Sign In / Providers > Email.
2. Keep Email provider enabled.
3. Turn OFF "Confirm email" / email confirmations.
4. Save changes.
This is required so signUp returns a session immediately. Customers still provide an email address, but they do not receive or need a verification email.

STEP 3 — DEPLOY THE TWO EDGE FUNCTIONS (REQUIRED)
These functions are needed for username login and secure admin password resets. They keep the Supabase service-role key on the server, never in the website.

Install/use Supabase CLI, then open PowerShell in this project folder and run:
  npx supabase login
  npx supabase link --project-ref mkmenxlmfcevtyzbnvfk

Set the admin email secret to EXACTLY the same email as VITE_ADMIN_EMAIL in your .env file:
  npx supabase secrets set BALAJI_ADMIN_EMAIL=your-admin-email@example.com

Deploy both functions:
  npx supabase functions deploy customer-login
  npx supabase functions deploy admin-customer-management

Supabase provides SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY to deployed Edge Functions. Never paste the service-role key into .env, React code, GitHub, or Cloudflare Pages.

STEP 4 — FRONTEND ENVIRONMENT
Keep the existing .env file at the project root (same folder as package.json). It should contain:
  VITE_SUPABASE_URL=your-existing-project-url
  VITE_SUPABASE_PUBLISHABLE_KEY=your-existing-publishable-key
  VITE_ADMIN_EMAIL=the-same-admin-email-as-the-edge-function-secret
  VITE_STORE_WHATSAPP=your-store-whatsapp-number
Do not share the values publicly. Do not use a service-role/secret key in VITE_ variables.

STEP 5 — BUILD AND DEPLOY
  npm.cmd install
  npm.cmd run build
Then publish the updated project to the GitHub repository connected to Cloudflare Pages. Ensure Cloudflare Pages has the same VITE_ frontend environment variables and redeploy.

HOW PASSWORD RESET WORKS
1. Customer selects "Forgot password? Contact store" and contacts the store.
2. Store verifies the customer's identity using known order/mobile details; do not reset solely because someone knows a username.
3. Admin signs into the existing Admin dashboard > Customers & Passwords.
4. Search the customer and click Generate temporary password.
5. Share the one-time temporary password privately with the verified customer.
6. On the customer's next login, the account page requires them to set a new password.
7. Hide the temporary password in the admin screen after sharing it. It is displayed only in the current admin session.

SECURITY
- Customer passwords are managed by Supabase Auth; this project never stores plaintext passwords.
- Username-to-email resolution happens in the server-side customer-login Edge Function.
- The admin-customer-management Edge Function checks the signed-in admin email before listing customers or resetting passwords.
- The service-role key is only available inside Supabase Edge Functions.
- Customer profile and order RLS policies restrict customers to their own data. Admin customer listing is not exposed directly through the browser database API.
- A temporary password should be delivered only after checking the customer's identity. Do not send it to an unverified requester.

COST

- No SMS OTP or SMTP verification email is used for signup.
